# LLM 任务评估改造记录（2026-10-29）

按照用户确认的方向，任务合理性、产物完成情况、质量分数和缺陷由 LLM 判断。
本次改造使用 `karpathy-guidelines` 和 `deslop`，以 `54362ef` 为修改前基线，
继续使用现有 `feat/evaluation-rsi-hardening` 分支。

## 当前行为

`SharedAssessment` 收集原任务、授权输入、成品观测和可用的实际渲染页，调用一次
任务级 judge。模型返回任务是否明确可行、PASS/PARTIAL/FAIL/NEEDS_REVIEW、
完成度、理由、证据引用和问题。状态及完成度原样传递；报告只做 0–1 与 0–100
的单位转换。模型可以给出 PASS/0.37、PARTIAL/0.84 或 FAIL/0.8，代码不会根据
这些分数另行覆盖状态。这些组合在测试中用于证明模型决定权，不代表校准建议。

`ArtifactEvaluator` 适配报告，`ArtifactVerifier` 传递模型问题和修复建议。
内循环冻结 skill 并修改产物；外循环修改 skill、重新执行任务并比较同一协议的
模型结果。候选修改范围、预算、隔离、统计、版本和回滚继续由代码管理。

没有 judge、调用失败或证据超出配置上限时，质量分保留 null，不回退到规则或
关键词评分。引用不存在的证据属于响应错误，原始回复保留，不编造产物缺陷。
模型判断 NEEDS_REVIEW 时保留该状态和空分数。
